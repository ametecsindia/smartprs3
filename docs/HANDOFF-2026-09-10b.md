## 2. The seven laws (SPINE §S1) — every review is against these

1. No business literal in code.
2. No runtime schema change — the application never adds a table or a column.
3. Nothing overwritten: versioned and effective-dated.
4. Every number explains itself.
5. Authorisation server-side, fails closed.
6. Tenancy is structural, not a where-clause somebody remembers.
7. Money is exact — never a float, anywhere, including previews.

Recurring lesson, earned repeatedly: **a check that silently checks nothing is
worse than a missing check.** NOT CHECKED / UNKNOWN / NOT PROVEN are reported
states, never blanks.

## 5b. Continued 10 Sep — fixes, Roles rewrite, three feature adds, a near-miss

**Fixed: `composer db:migrate` was destructive.** It ran `migrate.php --fresh`, which
`DROP DATABASE`s unconditionally before rebuilding — every session telling the owner to run it
was actually telling him to wipe his own data (companies/branches/departments/designations/rules/
formats, everything), which is almost certainly what caused the data loss he'd been blaming on
direct edits. Fixed: `db:migrate` now runs `migrate.php` with no `--fresh` (its own default is
migrate-forward-only, never drops). **Not yet confirmed solid by an actual run** — re-read
`composer.json` + `tools/db/migrate.php` before ever telling the owner to run it again. No
backup/undo exists for a past `--fresh` run inside the app; only a prior `mysqldump` or MySQL
binlogs (`C:\laragon\data\mysql-8.4\binlog.*`, needs someone with terminal access — Shashank) can
recover lost rows, and binlogs rotate, so this is time-sensitive.

**Fixed: browser rejected decimal values on module number fields** (e.g. "4.5" on Working
Shifts' Half Day (hours)). The generic module engine's `<input type="number">` rendered no
`step`/`min`/`max` at all, defaulting the browser to whole numbers only, even though server-side
validation already accepted decimals. One fix point (`public/app.php`, the field-loop's plain
`<input>` branch) — every module number field routes through it.

**Roles & Permissions rewritten to per-permission-code grain** (`surface/screens/roles.php`,
`surface/RoleMatrix.php`, `surface/Authorisation.php`). Previously every nav item sharing a
module's first segment (`employee.view`, `employee.create`, …) collapsed into one togglable row;
now each is its own row (No access / View / Edit / Full access). Filters: Role (the 3 enforced
roles) and Designation (from the live `designations` table, keyword-matched to a role via
`roleOfDesignationText()` — a shared helper in `public/app.php`, also used by the Payslip Format
Designer's Role scope below, so the two screens read a free-text designation the same way).
Fixed a same-day site-wide fatal this rewrite caused: a stale module-keyed override entry threw
inside `Permission::of()` on every request; `Authorisation::withOverride()` now catches that.
Owner has said he wants genuinely custom/dynamic roles eventually (not just these 3) — flagged as
a separate, bigger build, not started.

**Payslip format — Role filter + header toggles** (`surface/PayslipFormats.php`, route
`payslip-format`). Added a `role` scope dimension alongside company/branch/team/designation/
employee, and five per-format toggles — `show_logo` (gates the company's own `logo_path`),
`show_pan`, `show_uan`, `show_designation`, `show_doj` — all defaulting TRUE so no previously
saved format's output changes. The real payslip page resolves role and renders each field
conditionally from the employee's own columns.

**Salary structure — Calc. mode column** (`surface/ComponentRules.php`, route `structure`).
Per-row `calc_mode` (Custom / As per Government rules) stored in the row's existing `detail` JSON
(no migration needed — `detail` is the declared place for a shape nothing queries on). Sits right
after Company. Selecting "As per Government rules" disables every other control in THAT row only
— confirmed genuinely per-row/per-company, no shared lock state. No statutory engine was built;
this is presentation/locking only, as asked.

**ID card format — Visitor prints "VISITOR", Emp ID locked** (`public/app.php`'s
`configure-id-card` route + `surface/IdCardPdf.php`). The pre-existing Visitor sentinel scope now
prints bold enlarged "VISITOR" text in the photo box (live preview, first paint, and the PDF)
instead of a photo, and disables the Emp ID field toggle. Separately confirmed, not fixed: the
multi-named-format system (`IdCardFormat::entries()`/`formatFor()`, most-specific scope wins) was
already correctly wired into the real PDF-generation route — the owner's "does it apply the right
format per company/branch/designation" concern was already true.

**⚠️ Near-miss, now a standing rule: spawning a subagent on a shared file you have uncommitted
local edits to silently destroys those edits.** A subagent's own `device_stage_files` call
overwrites the local copy with whatever is currently on the device — it happened to in-flight
Payslip Format Designer work when a Salary Structure subagent was spawned mid-edit, and had to be
reconstructed twice. Rule going forward: commit and device-verify your own edits to a shared file
(especially `public/app.php`) BEFORE spawning any subagent that also touches it; run multiple
subagents touching the same shared file sequentially, never in parallel; instruct each to
re-stage and diff immediately before its final commit and MERGE onto unfamiliar-but-plausible
content rather than force-overwrite. Full detail in project memory (`phase1_sprint0.md`).

All four fixes/features above were re-verified together in one final pass (simultaneous re-stage
of every touched file, `php -l` clean, feature markers coexisting) before this note was written.

## 9. Traps this session actually fell into

- **`$field + ['type' => …]`** — PHP's union keeps the LEFT key, so it silently
  discarded the customer's chosen type. `array_merge`.
- **`(float)` on a preview amount** — the gate caught it. Law 7 has no exception
  for a number that is only being looked at.
- **MySQL names the wrong column** on a prepared-insert truncation (it reports by
  the table's ordinal). `SqlStore::put()` now attaches the shape of the row —
  column, type, size, never the values — to any refused write. That is what found
  a stale `surface/Trail.php` on the owner's machine writing a 21-character `id`
  into a bigint.
- **Shipped files can lag the build.** Compare sizes with `device_list_dir`
  before assuming an installation matches.
- **`write()` is refused on a tenant-scoped store** (it would delete other
  tenants' rows). Use `put()` per row; delete by retiring.
- **`?r=…&id=` means an employment everywhere.** A screen that answers `id` with
  something else makes the scope sweep report a false leak, which teaches people
  to ignore the sweep. The payslip designer uses `?format=`.
- The owner's tenant being empty makes correct screens look broken. Check the
  tenant before debugging.
